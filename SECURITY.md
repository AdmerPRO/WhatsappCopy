# Security Policy

## Supported Versions

The following versions of this project are currently supported with security updates:

| Version | Supported |
|---------|-----------|
| Latest  | Yes |
| Older versions | No |

Security updates are provided for the latest stable release. Users are encouraged to keep their installations up to date.

## Reporting a Vulnerability

If you discover a security vulnerability, please report it responsibly.

**Do NOT disclose security vulnerabilities publicly through GitHub Issues or Pull Requests.**

Instead, please report vulnerabilities using one of the following methods:

- **GitHub Security Advisories:** Use the "Report a vulnerability" feature in the repository's Security tab.
- **Email:** Contact the maintainers at [security@admerpro.com].

## What to Include

Please include as much information as possible in your report:

- A clear description of the vulnerability.
- Steps to reproduce the issue.
- Potential impact and severity.
- A proof of concept (PoC), if available.
- Affected versions.
- Suggested mitigation or fix, if known.

## Response Process

After receiving a vulnerability report, the maintainers will:

1. Acknowledge receipt of the report within 72 hours.
2. Investigate and attempt to reproduce the vulnerability.
3. Assess its severity and potential impact.
4. Work on a fix or mitigation.
5. Coordinate disclosure with the reporter.
6. Publish a security advisory when appropriate.

## Disclosure Policy

We request that security researchers:

- Allow maintainers reasonable time to investigate and fix reported vulnerabilities.
- Avoid publicly disclosing vulnerabilities before a fix is available.
- Do not exploit vulnerabilities beyond what is necessary to demonstrate their impact.
- Do not access, modify, or delete other users' data.
- Do not perform attacks that could disrupt the availability of the service.

## Scope

This policy applies to security vulnerabilities affecting:

- The project's source code.
- Official releases and distributions.
- Dependencies maintained or bundled by the project.
- Official infrastructure and services, where applicable.

## Safe Harbor

We consider security research conducted in accordance with this policy to be authorized.

We will not pursue legal action against researchers who:

- Make a good-faith effort to avoid privacy violations and service disruption.
- Follow this responsible disclosure policy.
- Report vulnerabilities promptly and privately.

This safe harbor does not authorize activities that violate applicable laws or affect third-party systems.

## Recognition

We appreciate everyone who helps improve the security of this project.

With the reporter's permission, we may publicly acknowledge their contribution in the relevant security advisory or release notes.
